## Why this project

Most e-commerce tutorials stop at a single CRUD app. I'm building a backend that looks like the systems I'd work on in a team: clear domain boundaries, a security layer that doesn't leak into business code, and services that can be built, tested and deployed independently.

## Where it stands

This is an **early-stage, in-progress** project. The Spring Boot 3 application on Java 21 is in place, along with the core **domain model** — users and their roles, products, addresses and the order lifecycle — mapped with Spring Data JPA on an in-memory H2 database for fast iteration.

## Roadmap

The architecture diagram shows the **target** design, built in this order:

1. **Domain-split services** for catalog, cart and order, each with its own REST API documented through OpenAPI.
2. **Stateless security** with Spring Security and JWTs carrying roles, enforced per service.
3. **Tests that matter** — unit tests with JUnit and Mockito, integration tests against real PostgreSQL via Testcontainers, all running in GitHub Actions.
4. **Asynchronous order flow** with events over Kafka, and the whole stack running from a single Docker Compose file.

Follow the repository to see each step land.
